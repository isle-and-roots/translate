# 設計判断: 自作実装から Sokuji へ

## 経緯

| | 旧実装（PR #1 / #2） | 現行（このリポジトリ） |
| --- | --- | --- |
| 本体 | 自作 Chrome 拡張（MV3, offscreen + WebRTC）+ Cloudflare Worker（短期トークン発行） | [Sokuji](https://github.com/kizuna-ai-lab/sokuji) v0.41.0 をサブモジュールで固定 |

## なぜ置き換えたか

1. **配線の排除** — 旧実装の最大のリスクは BlackHole の手動配線（特に Zoom アプリの 16ch/2ch 二重構成）でした。誤配線で日本語の生声が相手に届く、またはループするおそれがありました。Sokuji は会議アプリに直接仮想マイクを見せるので配線ミスが起きません。
2. **運用面** — Cloudflare Worker、接続コード、拡張 ID と CORS の突合が不要になり、シークレットは OpenAI キー 1 つになります。
3. **保守** — 上流は活発に更新されており（v0.41.0 時点で 9 プロバイダ、Meet / Zoom / Teams 等 13 サイト）、会議アプリ側の UI 変更への追従を自分で行う必要がなくなります。

## 相手音声の扱い

旧実装は相手の英語を日本語の合成音声としてイヤホンに流していました。Sokuji の「両方」モードは **相手の発話をテキストで翻訳** し（Participant client は text only）、音声合成は自分の声にだけ使います。上流ドキュメントの `two-way-voice` シナリオも「相手はあなたの翻訳音声を聞き、あなたは相手の字幕を読む」と定義されています。

- サイドパネルまたは字幕オーバーレイで日本語字幕を読む運用になります
- 相手の**原音**はそのまま聞こえます（拡張ではタブ音声のパススルー、アプリではそのまま）
- 相手側の翻訳を音声でも聞きたい場合、Sokuji では Soniox プロバイダの two-way モード（speech-to-speech・別契約）が候補ですが、本リポジトリの標準構成は OpenAI + 字幕です

この差分を受け入れられない場合は、上流に「participant 側の TTS」を要望する、または旧実装（PR #2）を継続するかの判断が必要です。

## ライセンス

Sokuji は AGPL-3.0 です。

- 本人が自分の端末で使う: 追加の義務なし
- ビルドした拡張・アプリを他人に配布、または SaaS として提供: AGPL-3.0 の条件（ソース提供、同ライセンス）が及ぶ
- このリポジトリは Sokuji を改変していません（ビルドフラグと手順のみ）。改変する場合は fork を作りその fork をサブモジュールにしてください
